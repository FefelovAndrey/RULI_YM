# AS IS — процесс Яндекс Маркета в YMWB

> **Вне скоупа RULI.** Канон исполнения FBS: [fbs-fulfillment-wa.md](fbs-fulfillment-wa.md), прогон и доработки: [../briefs/fbs-test-2026-09-01.md](../briefs/fbs-test-2026-09-01.md). Ниже — историческая съёмка YMWB, не контур Shop.

Статус: `draft`  
Источник: `repo: YMWB` · evidence: `../evidence/code/ymwb-yandex-market.md`  
Обновлено: `2026-08-27`

Модель продаж в коде **предполагается FBS**: в лист «ЯМ» всегда пишется `"FBS"`. FBY/DBS/экспресс в API не читаются и не ветвятся.

## Границы процесса

| In (YMWB делает) | Out (YMWB не делает) |
|------------------|----------------------|
| Пересчёт локальных остатков/цен | Создание/маппинг карточек в кабинете ЯМ |
| PUT остатков на кампанию | Приёмка / отмена / смена статуса заказа в ЯМ |
| POST цен на business | Ярлыки, короба, отгрузка, трекинг |
| GET заказов PROCESSING/STARTED | Возвраты, претензии, чат с покупателем |
| Telegram + запись в КАЗНА/ЯМ | Webhooks ЯМ, 1С, PIM, MPS |

Карточки офферов должны **уже существовать** в кабинете; ключ стыковки — `offerId` / `sku` = колонка `Sklad`.

## Happy path (цикл каждые ~5 мин)

1. **Обновить локальный склад.** Google Sheets «КАЗНА / СКЛАД» → `!YMWB.db.prices` (поставщик Sklad) → пересчёт `marketplace` (выбор поставщика, Нал, Опт, Цена).
2. **Опубликовать остатки.** Строки `Маркетплейс='yandex'` → `PUT /campaigns/{campaign_id}/offers/stocks`.
3. **Снять новые заказы.** `GET /campaigns/{campaign_id}/orders?status=PROCESSING&substatus=STARTED`. Для каждого неизвестного id: списать остаток → строка в «КАЗНА / ЯМ» → Telegram. Если были новые заказы — повторный PUT остатков.
4. **Опубликовать цены.** `POST /businesses/{businessId}/offer-prices/updates`.

Оператор может запустить тот же цикл вручную (`/automation/run`) или править каталог в UI `/table/yandex`.

## Подпроцесс: выбор поставщика и остаток

1. Если флаг поставщика Sklad включён и в `prices` по артикулу `Sklad` наличие ≥ 1 — источник **Sklad**.
2. Иначе среди Invask / Okno / United (включённых, наличие > 0) берётся **минимальный ОПТ**; при равенстве — порядок Invask → Okno → United.
3. Внешний поставщик: наличие **< 3 → 0**.
4. `Статус = выкл.` или маркетплейс OFF → `Нал = 0`.
5. Цена: `round((Опт + Опт × % / 100) / 100) × 100`. Для API ЯМ `discountBase = ceil(Цена × 1.18 / 100) × 100`.

---

## Подпроцесс: новый заказ ЯМ

1. Фильтр только `PROCESSING` + `STARTED` (остальные статусы ЯМ игнорируются).
2. Дедуп по `System/order_ids.txt`. Ошибка обработки → id **не** пишется → повтор на следующем цикле.
3. Позиции: `items[].offerId` (= Sklad), `count`, цена = `buyerPrice + SUBSIDY`.
4. Списание: если выбран Sklad — минус в Google Sheets «СКЛАД»; иначе минус в `marketplace` и `!YMWB.db`.
5. Операционный статус для склада: колонка M = **«На сборке»**. Дальше сборка/отгрузка — вручную вне системы.
6. Статус заказа в Partner API **не меняется**.

Внутренний аудит (`control_center.db`): `detected → parsed → stock → google_sheets → telegram → completed`.

## Ветвления / исключения

| Ветка | Когда | Что делают сейчас |
|-------|-------|-------------------|
| ЯМ выключен | `stock_flags.yandex = false` | Перед OFF — PUT нулевых остатков; локальный Нал=0 с бэкапом; цикл пропускает YM |
| Поставщик выключен | `stock_flags.suppliers.*` | Не участвует в выборе; пятница 01:00 OFF / воскресенье 15:00 ON для внешних |
| Товар «выкл.» | `Статус` | Нал=0, в ЯМ уходит ноль |
| Заказ при нуле Sklad | наличие 0 в «СКЛАД» | Telegram «заказ при нулевом остатке», обработка продолжается |
| Qty > 1 | `items[].count > 1` | Маркер в Telegram; списывается qty |
| HTTP ≠ 200 | любой из 3 методов | Telegram error-chat; шаг цикла = error, остальные шаги идут |
| Цикл уже идёт | lock | Новый запуск skipped_locked |

## Точки боли и костыли

- Каталог ЯМ ведётся **вручную** (UI + кабинет), нет API карточек — рассинхрон `Sklad` ↔ `offerId` не детектится.
- Фулфилмент обрывается на «На сборке»: нет приёмки, ярлыка, отгрузки, трекинга, отмены.
- Polling 5 мин + фильтр только STARTED: можно пропустить/задержать заказы в других substatus.
- `UPDATE marketplace SET Нал WHERE Sklad=?` **без** фильтра маркетплейса — списание ЯМ может обнулить ту же артикул-строку WB/Ozon.
- `FBS` хардкод в КАЗНА, не из API.
- Нет `warehouse_id` в payload остатков ЯМ (кампания подразумевает склад кабинета).
- Цены уходят **пачкой всех** офферов ЯМ за один POST; нет chunking / poll task status.
- Модуль `clients.http_client` отсутствует в репозитории — рантайм зависит от неучтённого файла.

| Факт | Человек / Excel / система |
|------|---------------------------|
| Карточка/offerId на ЯМ | Кабинет Яндекс Маркета (вне YMWB) |

| Остаток внешних поставщиков | `!YMWB.db` таблица `prices` (источник загрузки в этот репозиторий не ЯМ) |

| Задача на сборку | Google Sheets «КАЗНА / ЯМ», статус «На сборке» + Telegram |
| Включён ли канал ЯМ | `System/stock_flags.json` |
