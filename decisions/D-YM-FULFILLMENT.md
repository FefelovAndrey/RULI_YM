# D-YM-FULFILLMENT — где закрывать FBS-исполнение заказа ЯМ

Статус: `accepted`  
Дата: 2026-09-01

## Контекст

Q-005: нужно ли RULI закрывать приёмку / ярлык / отгрузку по Partner API, или достаточно сигнала в Трекер/Sheets.

Прогон sandbox **2026-09-01** (Маркет `61089913793` / Shop `2534310`) показал: цепочка **уже есть** в WA (`ym` + `clabels` + `rulimpsupplies`), не в YMWB и не только в кабинете. Дыры — операторские и запись `shop_ym_order_state`, не отсутствие API.

## Варианты

### A — Довести существующий контур WA

Плагины Shop: `ym` (accept / статусы / PDF), `clabels` (сборка / READY_TO_SHIP / QZ), `rulimpsupplies` (first-mile).

Плюсы: путь проверен на стенде; те же люди и экраны, что Ozon/WB-сборка.  
Минусы: чинить дыры as-is (`ym_order_state`, гейт ярлыка, фильтры first-mile), не «написать с нуля».

### B — Новый сервис исполнения вне Shop

Плюсы: чистый контракт.  
Минусы: дубль сборки/ярлыка; ломает уже работающий стендовый путь.

### C — Человек в кабинете Маркета + сигнал в Sheets/Трекер

Плюсы: ноль разработки.  
Минусы: опровергнуто прогоном — API-шаги уже вызываются из WA; кабинет не заменяет Сборку.

## Решение

Выбран: **A**  
Почему: sandbox закрыл accept → READY_TO_SHIP → labels → SHIPPED из WA. Дальше — закрыть AC в `F-ORDERS`, не менять контур.

## Implications

- Затрагивает фичи: `F-ORDERS` (контракт доработок), позже first-mile в том же контуре
- Не затрагивает: `F-CATALOG` / карточки (`D-YM-CARD-GEN`)
- Откат: выключить кнопки YM на карточке; заказы в Маркете остаются
